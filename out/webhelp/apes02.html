Preparations

When reading the description below you need to watch out for the order of the argument to openssl. Sometimes it doesn’t matter but sometimes it does and the error message you get will not really be helpful. For example, calling “openssl req -new –nodes . . .“ will work but calling “openssl req –nodes –new . . . ” will not work and fail with an error message about unrecognized option “-nodes”. While logically this could be explained it’s not really helpful if you are not used to the idiosyncrasies of openssl. While we could use the default “/etc/ssl” as our working directory we do not recommend this. Instead we create a pristine directory with our own setup so we won’t disturb anything else. Later on it is also easy to create a safety backup of this directory. We will therefore create a new directory which we will use to hold all keys and intermediate files. Since openssl keeps track of all certificates we have signed by means of a simple textual database (and a serial number) we must also setup those initial helper files.

In this directory we will have four additional subdirectories:

  • “private” , Stores all private keys we create

  • “public”, Stores all public keys (signed certificates)

  • “csr” , Stores all certificate signing requests (public keys which have not yet been signed)

  • “newcerts”, Stores a copy all our signed certificates (the “openssl ca” command will automatically store a copy of all signed certificate in this directory).

Start by creating this directory structure as (we will name our root directory “ca”):

$> mkdir ca
$> cd ca
$> mkdir private
$> mkdir public
$> mkdir csr
$> mkdir newcerts

Now we create an empty file which later on will hod the the simple text database which “openssl ca” uses to keep track of all certificates that we sign (openssl will complain if this file doesn’t exist).

$> touch index.txt

We shall now create a config file for openssl. One way to do this would be to take the supplied standard openssl config file (in /etc/ssl) and modify a few lines. However, we will create our own smaller version so that we now the exact meaning of every single line we have in the config file. This config file will also have some useful defaults to save us some typing each time we create (or sign) a certificate. We will therefore create our own minimal “our_openssl.cnf” as follows (you should probably name this file after your site and remember to use that name in the commands that follows for clarity).

#======================================================================
# Simplified openssl config file based on distributed openssl file
# Version 1.0
#======================================================================


#######################################################################
# CA Definitions – point to section where all default values can be
# found.
[ ca ]
default_ca		= CA_default

#######################################################################
# "openssl ca" default parameters
[ CA_default ]

dir	= .
new_certs_dir	= $dir/newcerts
database	= $dir/index.txt
certificate	= $dir/public/ca_public.pem     # Our CA (root) certificate (public key)
private_key	= $dir/private/ca_private.pem   # The private key for our CA key-pair
serial	= $dir/serial

# In our case we will not really be using Certificate Revocation Lists
# but we include the setup for future use
crldir	= $dir/crl
crlnumber	= $dir/crlnumber      
crl 	= $crldir/crl.pem       

default_days	= 3650    # We sign certificates that are valid for ~10 years
default_md	= sha1    # The sha1 encryption method is recommended over the older md5
name_opt	= ca_default
cert_opt	= ca_default
preserve	= no
policy	= policy_match

x509_extensions = usr_cert
copy_extensions = copy   # Honor the certificatre

####################################################################
# The default policy for the CA when signing requests We only request
# that certificate is from the same country
[ policy_match ]
countryName             = match
stateOrProvinceName     = supplied   
organizationName        = supplied   
organizationalUnitName  = supplied   
commonName              = supplied   
emailAddress            = supplied   

#######################################################################
#Default values for use with “openssl req” command
[ req ]
default_bits		= 2048
default_md		= sha1
string_mask		= utf8only
distinguished_name	= req_distinguished_name
req_extensions	= v3_req    # Extensions to add when creating certificate requests
x509_extensions 	= v3_ca     # Extensions to add to self-signed certificates

#######################################################################
# Prompts and default values for the fields in the DN
[ req_distinguished_name ]
0.organizationName		= Organization Name
0.organizationName_default		= Aditus

organizationalUnitName		= Unit or department in organization
organizationalUnitName_default	= IT-Adm

emailAddress			= Email Address
emailAddress_max		= 64
emailAddress_default		= admin@aditus.nu

localityName			= City or district
localityName_default		= Sundbyberg

stateOrProvinceName		= State or Province Name
stateOrProvinceName_default	= Sundbyberg

countryName			= Country Code (2 letter code)
countryName_min		= 2
countryName_max		= 2
countryName_default		= SE

commonName			= Common Name (hostname, IP, or your name)
commonName_max		= 64

#######################################################################
# Extension values used when signing certificates as a CA
[ usr_cert ]
basicConstraints=CA:false
subjectKeyIdentifier=hash
authorityKeyIdentifier=keyid,issuer


#######################################################################
# For the normal case where we do not create CA certificate but only 
# ordinary client certificates
[ v3_req ]
basicConstraints=CA:false
subjectKeyIdentifier=hash

# Uncomment the following if you want the certificate request generated on this server
# to have several aliases for the common name. Unfortunately this parameter can not be 
# given on the command line. 
# (Alternatively this could be specified as “subjectAltName = DNS:example.com, 
# DNS:www.example.com” instead as a list as we have done it now.
# subjectAltName = @alt_names

# Alias name for this server when creating signing requests. These are just examples!!
# Uncomment the following section and set proper names
#[ alt_names ]
#DNS.1 = sigma1
#DNS.2 = sigma1.nil

#######################################################################
# Section to be added when we give the command line option -extensions v3_ca
# together with the x509 option meaning that this should be a self-signed 
# certificate, i.e CA=TRUE
[ v3_ca ]
basicConstraints        = CA:TRUE
subjectKeyIdentifier    = hash
authorityKeyIdentifier  = keyid:always,issuer:always

#EOF
