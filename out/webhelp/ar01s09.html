Setting up procmail

When postfix receives a mail it will by default store the mail in the mail spool directory (either “/var/spool/mail/user” or “/var/mail/user”).

Postfix offers no possibility of post-processing of the received mails. For example to run the received mails through a spamfilter (like spamassassin) and put all identified spams in a separate mail folder.

To solve this we tell postfix to send all the received mails that should be locally delivered through another program, in our case procmail. It is this program that will act as a Local Delivery Agent, LDA, and perform the last stage when incoming mails are store on disk.

Configuration file

Procmail is controlled with (yet another) configuration file which by default is in the home directory of the user receiving the mail .procmailrc) . The configuration file will contain rules on how to process the incoming mails, such as storing mails based on different criteria in different folders. It is even possible to have certain mails automatically trigger other external programs. A typical use of this would be a server where users can send a one line mail to have some useful information automatically sent back.

In order to tell postfix to send incoming mails to procmail we must add the following line in the postfix config file (/etc/postfix/main.cf)

mailbox_command = /usr/bin/procmail

The next step is to setup the configuration file for procmail. Since it is possible to write an entire book on how to write procmail filtering rule we will keep this example simple. The example rule file below will do the following:

  • we will enable logging in a separate log file for each user under the /tmp directory

  • if the mail is judged to be “normal” spam we store it in the folder “Junk”

  • if the mail have a very high spam score we just discard them by deleting them forever

  • if the mail has the word “Newsletter” in the subject or comes from a sender “*.news.com” we put it in a separate mail folder “Newsletters”

  • otherwise we store it in the default inbox

The home page for procmail has many more receipts that you can take directly. For example “Out of office” style of automatic replies.

Unfortunately the syntax for procmail configuration is not exactly intuitive (anyone who think that has spent too much time with mail servers) but the basic structure in this example file will get you a good start and will serve a good start for your own experiments. It would bring this tutorial too far off track to become a “How To Write procmail Filter rules” as well. Refer to the procmail documentation for details.

In Appendix B, Procmail recipes we also show some more example of procmail configuration recipes.

Example 1. Template for a procmail configuration file

#---------------------------------------------
# Standard setup for extra logging
#---------------------------------------------
VERBOSE=on
LOGABSTRACT=all
LOGFILE=/tmp/procmail-${LOGNAME}-`date +%Y%m`.log
MAILDIR=/srv/mail/${LOGNAME}
DEFAULT=${MAILDIR}/
INBOX=${MAILDIR}/

#---------------------------------------------
# Subfolders to filter mails in.  
# REMEMBER TO PUT TRAILING '/' AT # THE END 
# to mark the folders as being in maildir format
#---------------------------------------------
SPAM=${MAILDIR}/.Junk/
NEWSLETTERS=${MAILDIR}/.newsletters/

##--------------------------------------------
## End of setup. Now comes all the filer 
## rules.
##--------------------------------------------

#---------------------------------------------
# FILTER for Newsletters.
#---------------------------------------------
:0
^Subject:.*Newsletter
^From:.*news.com
{ }
:0 E
$NEWSLETTERS

#---------------------------------------------
# FILTER for spamassassin
#---------------------------------------------
:0
* < 512000
| /usr/bin/spamc
#---------------------------------------------
# Discard all spams with score >= 15
#---------------------------------------------
:0
* !^X-Spam-Level: \*\*\*\*\*\*\*\*\*\*\*\*\*\*\*.*
* !^X-Spam-Status: Yes, score=1[5-9]\.[0-9]
* !^X-Spam-Status: Yes, score=[2-9][0-9]\.[0-9]
{ }
:0 E
/dev/null

#---------------------------------------------
# Put all remaining spams in Junk folder.
# NOTE: This assumes spamassassin is configured
# to set the X-Spam-Flag: YES for identified
# spams.
#---------------------------------------------
:0
* ^X-Spam-Flag: YES
$SPAM

#---------------------------------------------
# Send the remaing mails to the inbox
#---------------------------------------------
:0
$DEFAULT

Note

By default procmail only supports “AND” rules, i.e. if you add a number of conditions before an action all of them has to be fulfilled for the action to be performed.

One of the most frequent questions newcomers to procmail have is therefore how to write “OR” rules, i.e. a rule that states that

if condition1 or condition2 is true then do action

The way around this is to realize that

“if A or B then do C”

is equivalent to

“if (not A) and (not B) then do nothing else do C”.

Any book on Boolean logic will give more details on this subject.
