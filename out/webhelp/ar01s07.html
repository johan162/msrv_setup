Setting up fetchmail

Fetchmail:s role is to fetch mail from remote hosts to our server and deliver the fetched mail locally. In order to fetch mail we must first setup a configuration file for fetchmail with the remote servers and there credentials where we want to fetch mail, this configuration file is /etc/fetchmailrc.

After fetchmail has logged in it will deliver the mails locally to our SMTP server just as if the mail had come from some remote SMTP server connecting to us.

There is one thing to keep in mind here though and that is that fetchmail only handles password when fetching mail. It cannot handle passwords in the local delivery. This means that our postfix setup must accept incoming mails that should be delivered locally without password (which is the normal). Since we have specified smtpd_recipient_restrictions with the option permit_mynetworks This will allow fetchmail to store mail locally without providing a password.

To be really secure we should restrict this further by only allowing access from within the server itself. This can be done by making sure that mynetworks_style=host is set and make sure that mynetworks is empty since that configuration variable has precedence (if that is set the mynetworks_style will be ignored).

Configuring fetchmail

In the documentation for fetchmail there are several examples on how to setup a basic configuration. So in this section we will show some examples of more complex setup which isn't available in the fetchmail documentation.

The advantage (if any) with fetchmail configuration syntax is that it is quite "chatty" and can be read almost as an English sentence.

Let's start with a very basic example. Assuming that the remote server is called “remotemail.com” and the server uses POP3 (not IMAP). Furthermore we assume the username is “joe” (both remote and local) and the password is “secret.

The following configuration line will handle this case:

poll remotemail.com proto pop3 user "joe" there \ 
with password "secret"  is "joe" here;

Let's now do a slightly more complex setup. In this setup we are connecting to an IMAP server over SSL/TSL (meaning that we need to connect on port 993) and we want to collect mail from both the “Inbox” folder as well as the “Junk” mail folder back to our server.

Furthermore we want to permanently delete mails that are rejected as spams by our own postfix server when fetchmail tries to deliver it.

defaults
        user "joe@remotemail.com" is "joe"
        set no softbounce
        antispam 501
        bad-header accept

poll imap.remotemail.com with proto IMAP port 993:
        SSL        
        folder 'inbox','Junk'
        password "secret";

There are a couple of unusual thing in this setup.

  • To make it more readable we first set up some default values that apply to all defined servers. We use this to first set the user we are collecting mail from. The second option requires some more explanations. If we fetch a mail from the remote server and when we try to deliver it to our own postfix server it is refused since it is considered a wrongly formatted mail. In this case fetchmail will normally leave the mail on the remote server. With this option set fetchmail will remove the mail from the remote server even when it was rejected by our own server, effectively deleting the mail without anyone ever receiving it.

    This might sound like a bad thing to do. However mail that are so wrongly formatted that postfix refuses to accept it as a proper mail are to 99.999% spams.

  • The antispam 501 line tells fetchmail to interpret an 501 error (Bad address syntax) from the local postfix server not as an error but as a signal that the delivered mail is interpreted as a spam by postfix. It will then discard the message and since “set no softbounce” is in effect. The mail will then also be deleted from the remote server.

    A common cause of this is that postfix with default settings refuses addresses which begin by an “-“ (hyphen). This might be unusual but it is actually allowed (see RFC 5321, RFC 5322) so in this case postfix is a bit picky.

  • The “bad-header accept” command allows fetchmail to collect mail even if some of the headers are incorrect.

  • We then specify that we connect to the IMAP server on port 993 and enable SSL.

  • To get mail from several folders we use the “folder” command and then just list the folders we want to collect the mail from

Before starting fetchmail check that you are happy with the default configuration in /etc/sysconfig/fetchmail such as poll interval. (Just keep in mind that some ISP gets a bit unhappy if you try to poll there server every minute or so.)

Tip

There is also a GUI tool fetchmailconf that can be used to ease the creation of fetchmail configuration files. You can install this with 

$> sudo zipper install fetchmailconf

Starting and enabling fetchmail at boot time

To manually start fetchmail give the command 

$> chkconfig –add fetchmail

You should also add fetchmail as a service that is started at the same time the server boots. You can do this via Yast or by giving the command

$> chkconfig –add fetchmail

This command will start fetchmail in the default run levels (most likely 3- multiuser with network and 5 - full X-window client)
