B. Procmail recipes

The first line of a procmail filter always starts with “:0” and the remaining letters controls the filtering process.

For example “h” will only filter on the mail headers, “c” will make a copy of the mail so that it is available to filters after the current filter. If there is no “c” then the filter will consume the mail and processing stops here and no more filters will be applied to the mail.

The problem of filtering on the “Subject:” field

While at first it might seem simple enough to filter out certain mails with a specific subject either as spam or some other reason it is in practice a lot more complicated. The problem is that the subject does not always have to be in plain text. Instead it is very common to have the subject in either quoted printable or in base64. Such an encoded string looks like =?charset?format?encoded text?= (this format is more specifically described in RFC1522) and it can also be followed by some text in plain format and then again by some encoded text. For obvious reason a lot of spam uses this format to make it much more difficult to do simple text matching.

Unfortunately there is no easy way around this and procmail does not have any built in “decoding” functionality so this has to be done manually.

To help with this the following small perl script can be used as a helper script. This script has been floated on the net and the author is unfortunately unknown to me (if you know please let me now and the proper credit will be given)

#!/usr/bin/perl
#
# Perl script to decode a subject string possible encoded with RFC1522 
# quoted printable or base64 encoding.
# Author: Unknown.

while (<>) {
  chomp;
  s/^[ \t]//;
  foreach (split(/(=[?].*?[?][BQ][?].*?[?]=)/i)) {
    if (($charset, $encoding, $txt) = /=[?](.*?)[?]([bq])[?](.*?)[?]=/i) {
      $encoding =~ tr/[BQ]/[bq]/;
      open PIPE, "echo '$txt' | mimencode -u -$encoding |";
      $_ = <PIPE>;
      close PIPE;
      chomp;
      }
    print $_;
  }
  }

Store this script a file and make the file executable (in the example below we will assume it is stored in /usr/bin/decode_subjheader ) In procmail we can then use formmail to first extract the subject header and then run that header through this perl script to get the decoded subject

For example the helper script can be used as:

SUBJECT = `formail -xSubject: | /usr/bin/decode_subjheader`
:0
* SUBJECT ?? (Newsletter.*)
$NEWSLETTER

The recipe above will first extract the subject header from the mail and run it through our decoder perl script and then store the decoded header in the variable SUBJECT.
