Generating the Apache HTTPS key-pair

We will now generate the key-pair that will allow HTTPS traffic. We will show two ways of doing this. The first (and simplest) is top just generate a key-pair which is valid for exactly one common name, i.e. the name you access the browser with. On a home network where you probably don’t have a DNS server you will most likely access the server via an IP address directly. The problem with only having one name in the certificate is that if you access the browser through some other methods (perhaps from outside your router with a completely different IP address) you might again get a warning about untrusted site even if you have imported browser public key.

The following command will generate a key-pair. As you can see we have added the suffix “_req” to the public key. That is to remind ourself that this will just be used as a certificate signing request, i.e. this public key has not yet been signed by our CA key-pari created in the previous step. After we have signed the key it will be named “https_public.pem” 

$> openssl req -new -nodes -keyout private/https_private.pem \
-out csr/https_public_req.pem -config ./our_openssl.cnf

Answer all the questions that you are now presented with. Keep in mind that every certificate must have a unique distinguished name that is made up of the fields like company name, city, department/unit etc. A recommendation is therefore to use “Web” (or Apache or similar) as the unit name to differentiate this certificate from the other mail certificate we need to create as a next step.

For future reference you should save all requests and keys. The request can be re-used if the certificate has expired. So far we produced the following new files:

  • csr/https_public_req.pem, This is the public key that we will sign with our CA keys

  • private/https_private.pem, This is our private key that will be loaded by Apache

It is now time to sign the public key with our CA key. This is done with the command

$> openssl ca -out public/https_public.pem -config ./our_openssl.cnf \
-infiles csr/https_public_req.pem

Note: The config file has to be given on the command line before the “-infiles” command!

Answer the questions and use the password for the private CA key we created in section E.3. We have now generated the files

  • public/https_public.pem, This is the signed public certificate for Apache

  • newcerts/<some_large_serial_number>.pem, A copy for our own record of the just created certificate. The naming is the serial number of the certificate.

This newly signed certificate is also recorded in our database file “index”
