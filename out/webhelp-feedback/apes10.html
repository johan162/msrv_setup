Summary

With the above steps we have created the key-pairs we need for both the Web-server as well as the mail servers (Dovecot2 and postfix). You should now take a backup of this directory and keep it in a safe place. When you later on upgrade your servers you should restore these certificates to avoid client warnings.

Since there is quite a lot of text in the previous section we just repeat the actual commands below that we used to create the key-pairs to make it clearer that it is not that difficult. Each command set first creates the key-pair and then signs it.

Caution

Remember to uncomment and set the “subjectAltName” in the configuration file if you want your certificates to be valid for multi-homed servers, i.e. servers that are accessed with several different DNS names (but only one IP-address).

Creating the CA (root certificate)

$> openssl req -new -keyout private/ca_private.pem \
-out csr/ca_public_req.pem -config ./our_openssl.cnf
$> openssl ca -create_serial -out public/ca_public.pem \
-selfsign -extensions v3_ca -config our_openssl.cnf \
-days 7000 -infiles csr/ca_public_req.pem

Creating the Apache HTTPS certificate

$> openssl req -new -nodes -keyout private/https_private.pem \
-out csr/https_public_req.pem -config ./our_openssl.cnf
$> openssl ca -out public/https_public.pem -config ./our_openssl.cnf \
-infiles csr/https_public_req.pem

Creating the mail certificate

$> openssl req -new -nodes -keyout private/mail_private.pem \
-out csr/mail_public_req.pem -config ./our_openssl.cnf
$> openssl ca -out public/mail_public.pem -config ./our_openssl.cnf \
-infiles csr/mail_public_req.pem
