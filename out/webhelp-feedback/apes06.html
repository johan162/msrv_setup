Generating a certificate with multiple common names

As mentioned above most people create certificates as we did above. However, for the case the same server is accessed through many names (for example “www.myserver.com” or “myserver.com” or “199.243.243.12” etc) this certificate will still generate a warning if we access the server with any other name besides what we used when we created the certificate signing request. To create a certificate with multiple alternative names requires some additional setup. In the preparation section our “openssl.cnf” contains all the necessary parameters but we need to uncomment them. First uncomment the line

copy_extensions = copy

Then uncomment and setup the lines at the end of the file

subjectAltName = @alt_names

# Alias name for this server when creating signing requests. 
# These are just examples!!
# Uncomment the following section and set proper names
[alt_names]
DNS.1 = example.com
DNS.2 = www.example.com
DNS.3 = 199.199.199.199

To match the values you want to have. The you can just generate the certificate as in the same way we did before (we just use a different name for the certificate to keep them apart)

$> openssl req -new -nodes -keyout private/https_alt_private.pem \
        -out csr/https_alt_public_req.pem -config ./openssl.cnf

Note: You must change some entry in the DN fields compared to the previously created HTTPS certificate since our Database for certificates we have signed must all have unique DN. You could for example change your CN (Common Name).

We can view the request to make sure that we have the alternative names included with the command.

$> openssl req –in csr/https_alt_public_req.pem –noout –text

and in the long output the following lines can bee seen

    Requested Extensions:
            X509v3 Basic Constraints:
                CA:FALSE
            X509v3 Subject Key Identifier:
                7A:2E:34:23:E5:EB:D3:15:56:9F:8E:D9:07:13:6C:7D:14:40:E1:B2
            X509v3 Subject Alternative Name:
                DNS:199.199.199, DNS:example.com, DNS:www.example.com
                . . .

The ones marked with red states the alternative names that can be used with this certificate. It is now time to sign it the certificate

$> openssl ca -out public/https_alt_public.pem -config ./openssl.cnf \
-infiles csr/https_alt_public_req.pem

And after this command we have the following new files

  • public/https_alt_public.pem

  • private/https_alt_private.pem

  • csr/https_public_req.pem

  • newcerts/03.pem
