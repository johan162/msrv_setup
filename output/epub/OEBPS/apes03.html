E.3 Generating the CA key-pair

We are now in position to generate our root (CA) certificate. The first step is to create the key-pair and the signing request

$> openssl req -new -keyout private/ca_private.pem -out csr/ca_public_req.pem \
-config ./our_openssl.cnf

The next step is for us to sign it our self

$> openssl ca -create_serial -out public/ca_public.pem -selfsign -extensions v3_ca \
-config our_openssl.cnf -days 7000 -infiles csr/ca_public_req.pem

This will prompt you for a number of things most of them have default values as specified in the config file. Do not forget the password you gave here for the CA private key.

The special options used for the CA signing as compared to all the signings we will do from here on are he two options

  • -selfsign, Which tells openssl to use the ca_public_req.pem when signing instead of expecting a CA certificate (which we haven’t created yet)

  • -extension v3_ca, needed to read the v3_ca section in the config file.

Our CA certificate (root certificate) will be valid for roughly 20 years (~7000 days). We have now produced the following files:

  • private/ca_private.pem, The password protected private key part of our CA-key pair. This file should be kept secret at all times!

  • public/ca_public.pem, The public key that should be imported into browsers that we want to accept any other public leys (certificates) that we will sign in the future.

  • csr/ca_public_req.pem, The signing request for our CA

  • serial, This is an administrative file used by “openssl ca” to give a unique serial number for each of the certificate that we sign.

  • newcerts/<random_serial_number>.pem, A copy of our signed certificate. The exact name is random since it starts with the serial number that was randomly generated. From this moment on each serial number will be incremented by one for each new certificate that we sign.

Many other tutorials show what seems to be a simpler way to create root certificate in only one step using the –x509 option with openssl. As in 

$> openssl req -new -x509 -extensions v3_ca -keyout private/ca_private.pem \ 
-out public/ca_public.pem -days 7000 -config ./our_openssl.cnf

However, we do not recommend this way since it has a number of drawbacks:

  • You cannot use –create_serial with the “req” command

  • The signing request is not kept

  • There is no copy for our signed root certificate in newcerts as it is with all other cert we created

This could however be used in another way. If you need to quickly create a “test-certificate” (which isn’t signed by any trusted authority or yourself) you could create such a certificate in the same way (no need to include the –extensions v3_ca in this case though) such as 

$> openssl req -new –nodes -x509 -keyout private/tstcert_private.pem \ 
-out public/tstcert_public.pem -days 7000 -config ./our_openssl.cnf

You can now use the resulting certificate if you need to run some quick test with some software that requires a SSL/TLS certificate (key-pair).

Note

Note on x509v3 compliancy. The CA certificate we have created here is, while perfectly working, not formally fully compliant with the very latest version of the PKIX and X509v3 standards since that requires the email address to be specified in a slightly different place. This is however of no practical concern for us (unless you plan on starting your own worldwide certification agency and charge money for signing certificates)
