E.9 Certification Revocation List (CRL) and OCSP

One thing that we haven't yet touched upon is the directory crl/ under the apache configuration directory. This directory is used to store a Certificate Revocation List. Basically a list of certificates that the issuer might revoked and should no longer be trusted. From the server perspective this is used to verify that any certificate a client might present is still valid.

The problem with such a revocation list is that it must be constantly renewed to be of any value. In addition both the client and the server needs to have access to an updated revocation lists since neither part can really trust the other part.

For the reason with the need of constant updates of the revocation lists this has too large extent been replaced by online direct checking using what is known as OCSP (Online Certificate Status Protocol). Basically the client will verify any certificate given by the server by going online and check a central revocation lists on a dedicated certificate server.

Ideally all official root certificates (CA certificates) will have ps59D7005DKsuch a server. So for example if a server claims to have a certificate verified by, say, Verisign the client will go online to the Verisign OCSP server and double check that the certificate is really still valid.

We will not discuss this any further in this tutorial but should the need to setup a certificate server arise the open source server "OpenCA" (http://www.openca.org/\) server might be good candidate to examine since it also includes a OCSPD server daemon.
