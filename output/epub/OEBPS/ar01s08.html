8 Setting up spamassassin

Spamassassin is a Perl based program/script that uses statistical analysis of text to determine the likelihood that a certain mail is a spam or legitimate mail. Spamassassin is one of the oldest spam filter but has been regularly updated and is good enough for small scale home based server. The main complaints for a large scale setup of is not the quality of the analysis but rather that it requires quite a lot of computing power and can take several ms to scan each mail. In a large (several thousand mails an hour) setup this can become a bottleneck and a separate server might nede to be deployd for this prpose..

However there is one way to speed things up and reduce the system load and that is the spamd/spamc daemon/client setup. This allows spamassassin to remain running in the memory and avoids starting up a Perl process and shut it down for each mail to be scanned. This is also installed by default (but not enabled). To call the resident daemon the client spamc is used. This is also the client program we call from within our procmail script to run the mails through the spam filter.

To enable the spamd daemon either enabled it via Yast System Services (runlevel) editor or via the command line 

$> chkconfig –add spamd

After installing spamassassin via Yast there are several places where the configuration files reside.

  • /usr/share/spamassassin - This is where all the static rules are stored that gets installed with spamassassin. In here is also the file local.cf which is the only file that should be modified for local preferences since all other files will be overwritten in case of an upgrade. However it is recommended tht you do not make any modifications here. Instead use the config file under /etc (see next bullet)

  • /etc/mail/spamassassin/local.conf - This is only the proper place to do local modifications for server wide adjustments

  • <user home>/.spamassassin/user_prefs - This is the proper file to set user specific modifications

When spamassassin reads the configuration files it first reads the files under /usr then the files under /etc and finnaly the users home directory. If any file has the same name the later version will be added to the previous version so any changes in a later file will override previous changes.

The default settings are usually good enough for the majority of users but you may want to lower the default spam threshold of a score of 5.0 to something a bit lower, say 4. This change could be made in /etc/mail/spamassassin/local.conf to affect all users on the server.

It is important to understand that spamassassin by itself does not sort mails in any way. It simply adds a few headers in the mail indicating how likely the mail is to be a spam. It is then up to the rules in the procmail script to interpret these headers to determine if the mail should be put in the spamfolder or be received as a regular mail. The specific headers added by spamassassin are shown in table Table 7.

Spamassassin is in our setup run by procmail as an external program and run as the user who is receiving the mail. Procmail puts each mail who's size is less than a predetermined size through spamassassin and then looks in the headers to determine if the mail should be put in the spam folder, possible deleted forever or just forwarded to the normal inbox or perhaps some other mail folder. Review the procmail configuration in the next section for how this is done.

The reason to limit the size of mail we put through spamassassin to avoid having (for example) large mails with multimedia content to be run through spamassassin since that would consume a lot of time and spam mails are never (well almost) that large so that would just be a waste of server time.

8.1 Configuring spamassassin Bayes auto learning

Apart from the static analysis on headers and content of the mail spamassassin also has the ability to learn the particular words in typical spams. This later on helps spamassassin identify spams.

Bayes auto learning is enabled by default but you should also check that it is by checking that bayes_auto_learn 1

By default spamassassin learns word from mails and learns them as either spam or non-spam ("ham") depending on thresholds defined in the configuration file. By default these thresholds are rather high to avoid learning from false positive. You can be more aggressive here and for example use the following lower thresholds values.

#   Use Bayesian classifier (default: 1)
#
# use_bayes 1

#   Bayesian classifier auto-learning (default: 1)
#
# bayes_auto_learn 1

# Mail which scores outside this range will be fed back into SpamAssassin's
# learning system automatically, to train the Bayesian scanner.
ifplugin Mail::SpamAssassin::Plugin::AutoLearnThreshold
bayes_auto_learn_threshold_nonspam      0.01
bayes_auto_learn_threshold_spam         6.0
endif # Mail::SpamAssassin::Plugin::AutoLearnThreshold

The above changes can be made either in /etc/mail/spamassassin/local.conf to take affect side wide or in the ~/.spamassassin/user_prefs file to affect only a specific user.

If you have a folder with eihter spam or ham you can also instruct spamassassin to learn from that collection with the use of the "sa-learn" command. For example as

$> sa-learn --spam <folder/with/spam.mails>

8.2 Verifying spamassassin

To verify that the spamassassin daemon is running we can do a simple manual test by running some nonsense text through the spamassassin client spamc which in turns calls on spamd.

$> echo “Nonsense text” | spamc -R

You should now get a fairly long reply with the headers in table Table 7 clearly visible in a format that (almost) looks like the raw format of a mail.

Table 7: Headers added by spamassassin

Header

Description

X-Spam-Checker-Version:

Version information

Example: 

X-Spam-Checker-Version: SpamAssassin 3.3.1. 
(2010-03-16) on myhost.nil

X-Spam-Flag:

A flag YES or NO to indicate if the computer score is over the set spam threshold

Example: 

X-Spam-Flag: YES

X-Spam-Level:

A graphical indication with ‘*’ to indicate the computed spam score. Each ‘*’ represents one integer score.

Example: 

X-Spam-Level: ******

X-Spam-Status:

A detailed list with the numerical score, required score and list of tests that indicates that this might be a spam.

Example: 

X-Spam-Status: Yes, score=8.0, required=4.0 
tests=EMPTY_MESSAGE, MISSING_DATE,MISSING_MID, 
NO_RELAYS autolearn=no version=3.3.1
