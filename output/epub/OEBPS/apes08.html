E.8 Converting to other certificate formats

As mentioned previously there are other variant formats besides PEM used to store certificates and keys. More specifically there are two other formats commonly usedas described below.

E.8.1 DER format

File suffix: *.der

DER stands for Distinguished Encoding Rules. This format is also quite often used on MS Windows system as well as with Java. This is a binary format so it cannot directly be viewed as a text file (in opposite from the pem format).

Convert an existing certificate in PEM format to the equivalent DER format is straight forward using openssl

$> openssl x509 -inform pem -in certificate.pem -outform der \
-out certificate.der

E.8.2 PKCS #12 format

File suffix: *.p12

PKCS stands for [Definition: Public-Key Cryptography Standards] and #12 is a format in which both a private and a public key is stored in the same file for the purpose of authentication.

The PKCS format is part of a larger set of standards defined by the RSA Laboratories. Some of these standard are also defined as RFCs. This specific standard (#12) is a format used to store client certificates. Client certificates are used in analogy to server certificates but to identify the client and not a server. A server can for example be setup in such a way that a client must have a trusted certificate in order to connect to the server. The server trusts a specific certificate if the certificate have been signed by an authority accepted by the server.

It would bring to far to go through all the details of this format here. However this type of format is handled by the pkcs12 subcommand to openssl command.

To create a client certificate to be used for authentication based on a existing key-pair use the command

$> openssl pkcs12 -export -clcerts -in mypublickey.pem \
-inkey myprivatekey.pem -out myclcert.p12

One difference here is that the client certificate will be protected by a password so this will have to be given when the certificate is created (openssl will ask for it).

In order to view some details an existing client certificate use the following command

$> openssl pkcs12 -noout -info -in myclcert.p12
Enter Import Password: <SECRET_PASSWORD>
MAC Iteration 2048
MAC verified OK
PKCS7 Encrypted data: pbeWithSHA1And40BitRC2-CBC, Iteration 2048
Certificate bag
PKCS7 Data
Shrouded Keybag: pbeWithSHA1And3-KeyTripleDES-CBC, Iteration 2048

In the output there is a statements about "MAC verified OK". In this context MAC stands for [Definition: Message Authentication Code] and is a way to guarantee that the certificate is valid and has not been tampered with. The reference to PKCS #7 refers to specific message syntax which is detailed in RFC2315
